# Feature map 结构指南(抽象自 feature map 验证范式)

## 特性文件格式(每个用户可见特性一页)

- What it is:一句话说明特性是什么(用户视角,不是实现视角)。
- How to get to it:到达路径(菜单/命令/URL/快捷键),逐键可复现。
- How to use it:正常用法与关键状态;跨特性旅程单独一节。
- 相关文件:驱动该特性最相关的代码/配置路径(教「怎么用」,不教「怎么建」;内部实现读代码,不写进地图)。

## 基线前置条件(control-<app> 每次运行前逐条检查)

- 应用正在运行且健康(健康检查命令/接口给出明确信号)。
- 登录态与权限满足;无法自动完成的一步(如真实 OAuth)如实说明并交回人工。
- 工作区干净或状态已知;无遮挡窗口/模态框/挂起通知。
- 云端、远程、原生绑定路径需要对应权限/系统/驱动;不可达就跳过并在证明中说明。

## 证明约定

- 证明改动有效 = 用 control-<app> 真实驱动运行中的应用,逐条对照特性地图;不是读代码、不是「编译通过」、不是 agent 自报。
- 每条证明绑定可核验证据(输出、截图、日志、录制)。

## 漂移维护

- 特性地图是「维护中的验证源」;应用变化后地图漂移,按 maintain-verification-skill 的循环:源波扫描 + 一次实机通过,最多一个 PR 的已证实修正。
